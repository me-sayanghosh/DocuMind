# TESTING

Two kinds of quality here: **software correctness** (pytest/Vitest/E2E) and **answer quality** (the evaluation harness). Both gate releases.

## 1. Test pyramid

| Layer | Tools | Scope | Share |
|---|---|---|---|
| Unit | pytest, Vitest | chunker, RRF, metrics, prompt builder, permissions, components | ~60% |
| Integration | pytest + real Postgres/pgvector + Redis (testcontainers or Compose service) | routes + DB, ingestion, retrieval SQL, tenancy | ~30% |
| E2E | Playwright | upload → ready → chat → citation click | ~10% |
| Retrieval/answer eval | `make eval` | hit@k, MRR, faithfulness, citation accuracy | continuous |
| Non-functional | Locust/k6, axe | latency, load, accessibility | pre-release |

## 2. Backend testing

### Fixtures
- `tests/fixtures/pdfs/`: small text PDF, multi-page with headers/footers, table-heavy, scanned (no text), encrypted, corrupt, 300+ page, injection-laden PDF.
- Deterministic fake `Embedder` (hash-based vectors) for fast tests; real model used only in marked `@pytest.mark.slow` tests and eval.
- Fake `LLM` returning scripted streams including `[n]` markers; real Claude only in eval/manual runs.
- DB: per-test transaction rollback or per-module schema; migrations applied once via Alembic.

### Unit test targets
- Chunker: size/overlap bounds, no empty chunks, page numbers and bbox merging correct, unicode/ligatures handled.
- RRF: known rankings → expected fused order; ties stable; single-source input.
- Prompt builder: escapes `</source>`, enforces context budget, includes ordinals.
- Citation parser: `[1]`, `[1][3]`, invalid ordinals ignored, no citations → warning flag.
- Metrics: hit@k, MRR, recall computed on hand-built cases.
- Auth: password hashing, token expiry, `alg=none`, refresh reuse detection.
- Quota/rate-limit counters with fake clock.

### Integration test targets
- Register/login/refresh/logout flow with cookies.
- Upload → job runs inline (ARQ test mode) → `ready`; duplicate upload returns existing doc; failed parse sets `failed`.
- Retrieval: vector, FTS, hybrid return expected chunks on a seeded corpus; workspace and doc-scope filtering; HNSW filtered queries return k results.
- Delete cascades: chunks, citations (snippets retained), file removed.
- SSE chat: event order, refusal path, stop/cancel, persisted message and trace rows.
- **Tenancy matrix:** parametrize every route × {owner A, member A, user B, anonymous} and assert expected 200/403/404/401. Include chunk/citation ids belonging to another tenant in request bodies.
- RLS: direct SQL as app role without `app.user_id` returns zero rows.

### Coverage and static checks
Coverage ≥ 80% overall, ≥ 90% on `rag/` and `auth`. `ruff`, `mypy --strict` (app code), `bandit` (optional).

## 3. Frontend testing
- Vitest + Testing Library: Composer behavior, MessageBubble states, CitationChip hover/click, StatusBadge, `useChatStream` with mocked SSE frames (partial frames, errors, abort).
- MSW for API mocks.
- Unit test for bbox → CSS coordinate conversion.
- axe-core checks on Login, Library, Chat.

## 4. E2E (Playwright)
1. Register → login → upload fixture PDF → wait until `ready`.
2. Ask a question with a known answer → assert streamed text and citation `[1]`.
3. Click citation → viewer shows correct page and highlight element present.
4. Ask unanswerable question → refusal text.
5. Delete document → disappears; subsequent ask yields refusal.
6. Second user cannot see the first user's documents (separate browser context).
Run against Compose stack with fake LLM mode (`LLM_PROVIDER=fake`) in CI; real LLM smoke test nightly.

## 5. Evaluation harness (answer quality)

### Dataset
- Corpus: 5–10 public PDFs (papers, a contract template, a manual, a report) committed or downloaded by script; licensing noted.
- Questions: 100–200 generated by Claude from sampled chunks + 30 unanswerable + 30 keyword-heavy (IDs, clause numbers, names) + hand-written 20 "golden" items. Manually spot-check ~10% for validity. Split dev (70%) / held-out (30%); report held-out.

### Metrics
| Metric | Definition |
|---|---|
| hit@k (k=1,3,5,10) | gold chunk in top k |
| MRR | mean reciprocal rank of first gold chunk |
| Recall@k | share of gold chunks found (multi-gold questions) |
| Faithfulness | LLM judge: every claim supported by cited/retrieved context (0–1) |
| Answer relevance | judge: answers the question vs reference |
| Citation accuracy | cited chunk actually entails the sentence it's attached to |
| Refusal precision/recall | refuses unanswerable; doesn't refuse answerable |
| Latency | p50/p95 per stage |

### Ablations to publish
`vector` → `fts` → `hybrid (RRF)` → `hybrid + rerank`, and chunk size {300, 500, 800}, overlap {0, 80}, top-k {4, 6, 8}. Report as a Markdown table in the README with N and date.

### Judge reliability
Use a rubric prompt with structured JSON output; temperature 0; calibrate by hand-labeling 30 answers and reporting judge agreement.

### Regression gate in CI
A small fixture eval (20 questions, cached embeddings, fake or cached LLM judgments) runs on PRs touching `rag/`; fail if hit@5 drops by more than 3 points from the stored baseline.

## 6. Performance and load
- k6/Locust: 20 concurrent chat sessions on a 50k-chunk corpus; targets from NFR-1.
- Ingestion benchmark: 100-page PDF, record time per stage.
- `EXPLAIN ANALYZE` snapshots for dense and FTS queries stored in docs.

## 7. CI pipeline (GitHub Actions)

```
on: pull_request, push to main
jobs:
  backend:  services: postgres(pgvector), redis → ruff, mypy, alembic upgrade, pytest --cov
  frontend: npm ci → eslint, tsc, vitest, build
  e2e:      docker compose up → playwright (fake LLM)
  security: gitleaks, pip-audit, npm audit, trivy image scan
  eval-smoke: (paths: backend/app/rag/**) small eval + baseline compare
```
Required checks on `main`; nightly job runs real-LLM smoke and full eval.
