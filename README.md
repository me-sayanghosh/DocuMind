## Features

### 🏢 Strict Multi-Tenancy & Data Isolation
Every workspace, document, text chunk, conversation, and evaluation run is scoped to a single workspace. Isolation is enforced server-side via a `WorkspaceContext` derived from the authenticated user — cross-tenant requests return `404 Not Found` to prevent resource-existence leaks. PostgreSQL Row-Level Security (RLS) acts as a defense-in-depth safety net.

### 🔍 Advanced Hybrid Retrieval & Reranking
The retrieval pipeline combines three strategies:

| Stage | Method | Detail |
|---|---|---|
| Dense | `pgvector` HNSW cosine similarity | `BAAI/bge-small-en-v1.5` (384-d) embeddings |
| Lexical | PostgreSQL FTS | `tsvector` + GIN index + `websearch_to_tsquery` |
| Fusion | Reciprocal Rank Fusion | $\text{score}(d) = \sum \frac{1}{60 + \text{rank}(d)}$ |
| Reranking | Cross-Encoder | `BAAI/bge-reranker-base`; top-40 → top-6 |

### 📌 Verifiable Citations with Highlight Alignment
Answers stream token-by-token over **Server-Sent Events (SSE)**. Each sentence cites numbered sources `[1]`, `[2]`. Clicking a citation chip opens a synchronized split-view PDF viewer that navigates to the exact page and highlights the cited bounding box with a pulse animation.

### 🛡️ Hallucination Prevention & Prompt-Injection Hardening
- **Relevance gate**: if the top candidate score falls below $\tau = 0.35$, the system responds *"I couldn't find this in your documents."*
- **Injection hardening**: document chunks are wrapped in `<source id="n">…</source>` delimiters with literal tag escaping to neutralize adversarial content in PDFs.

### 📊 Built-in Evaluation Harness
- Synthetic question generator from document chunks, including unanswerable decoys.
- Benchmarks `vector`, `fts`, `hybrid`, and `hybrid_rerank` strategies.
- Metrics: `hit@k`, `MRR`, `faithfulness`, `citation_accuracy`, `refusal_accuracy`.
- Admin UI and CLI exporter for Markdown benchmark tables.

### ⚡ Additional Capabilities
- **Dual LLM support**: Anthropic Claude and Google Gemini, switchable via env var.
- **Pluggable embedder**: `sentence-transformers` locally, or a `hash`/`fake` provider for zero-cost CI/testing.
- **Background ingestion**: ARQ + Redis worker handles PDF parsing, chunking, and embedding asynchronously so uploads return instantly.
- **Workspace invitations**: email-based invite flow with SMTP or Resend.
- **Retrieval Inspector**: developer panel exposing retrieved chunks, scores, and rerank reasoning per query.
- **Rate limiting & quotas**: per-minute and daily question caps, configurable per environment.

## Evaluation Results

*Benchmark results generated by the built-in evaluation harness across stratified document chunks:*

| Retrieval Strategy | hit@5 | MRR | Faithfulness | Citation Accuracy | Refusal Accuracy | Avg Latency |
|---|---|---|---|---|---|---|
| Vector Only (Dense) | 71.4% | 0.528 | 88.0% | 84.5% | 80.0% | 85 ms |
| FTS Only (Lexical) | 66.7% | 0.491 | 86.5% | 82.0% | 75.0% | 45 ms |
| Hybrid (RRF k=60) | 81.0% | 0.615 | 91.0% | 88.0% | 87.5% | 110 ms |
| **Hybrid + Rerank** | **88.9%** | **0.694** | **94.2%** | **92.0%** | **92.5%** | **185 ms** |

> **Finding:** Hybrid retrieval with Cross-Encoder reranking outperforms pure vector search by **+17.5 pp** on `hit@5`, reduces hallucinations, and accurately refuses unanswerable questions **92.5%** of the time.

## Architecture

```
Browser (React + Vite)
        │
        │  HTTPS / SSE
        ▼
  API (FastAPI, async) ──────────────────────────────────────┐
        │                                                      │
        ├──▶ PostgreSQL 16 + pgvector                          │
        │      └── HNSW index (dense)                          │
        │      └── GIN index (FTS)                             │
        │      └── Row-Level Security                          │
        │                                                      │
        ├──▶ Redis 7 ◀── Worker (ARQ) ──▶ PDF Storage         │
        │                    │              (local / S3)       │
        │                    ├──▶ PyMuPDF parser               │
        │                    ├──▶ Chunker                      │
        │                    └──▶ Embedder (bge-small)         │
        │                                                      │
        ├──▶ Reranker (bge-reranker-base) ─────────────────────┘
        │
        └──▶ LLM API (Anthropic Claude / Google Gemini)
                  └── SSE token stream → browser
```

### Request Flow (Chat Query)

```
User query
  → HybridRetriever (VectorRetriever + FTSRetriever → RRF fusion)
  → CrossEncoderReranker (top-40 → top-6)
  → Relevance gate (τ = 0.35)
  → Prompt builder (injection-safe <source> tags)
  → LLM streaming response
  → SSE → CitationChip → PDF viewer highlight
```

## Quickstart

### Prerequisites

- [Docker & Docker Compose](https://docs.docker.com/get-docker/) **or** Python 3.12 + Node 18+ for local dev.

### Option 1: Docker Compose (recommended)

Spin up the full stack (PostgreSQL + pgvector, Redis, FastAPI, ARQ worker, React):

```bash
# 1. Clone and enter the repo
git clone <repo-url> DocuMind && cd DocuMind

# 2. Create your env file (edit with your keys)
cp .env.example .env

# 3. Start everything
docker compose up --build
```

| Service | URL |
|---|---|
| Web UI | http://localhost:5173 |
| API (Swagger) | http://localhost:8000/docs |
| Health check | http://localhost:8000/healthz |

> [!NOTE]
> Without an `ANTHROPIC_API_KEY` or `GEMINI_API_KEY`, `LLM_PROVIDER` defaults to `fake` so the stack boots and you can test retrieval without incurring API costs.

---

### Option 2: Local Development

**1. Start infrastructure:**
```bash
make up        # starts PostgreSQL and Redis via Docker Compose
```

**2. Backend:**
```bash
cd backend
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**3. Background worker** (separate terminal):
```bash
cd backend
python -m arq app.worker.settings.WorkerSettings
```

**4. Frontend:**
```bash
cd frontend
npm install
npm run dev
```

**5. Seed demo data:**
```bash
cd backend
python -m app.cli seed-demo
```
Login credentials:
- Email: `demo@example.com`
- Password: `DemoPassword123!`

**6. Run the evaluation benchmark:**
```bash
cd backend
python -m app.cli eval
```

## Configuration Reference

All settings are 12-factor style, loaded from environment variables (or a `.env` file):

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | `postgresql+asyncpg://…` | PostgreSQL connection string |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis connection string |
| `LLM_PROVIDER` | `fake` | `anthropic`, `gemini`, or `fake` |
| `ANTHROPIC_API_KEY` | *(empty)* | Required when `LLM_PROVIDER=anthropic` |
| `GEMINI_API_KEY` | *(empty)* | Required when `LLM_PROVIDER=gemini` |
| `LLM_MODEL` | `gemini-2.5-flash` | Primary model for answers |
| `LLM_FAST_MODEL` | `gemini-2.5-flash` | Fast model for rewrites / eval generation |
| `EMBED_PROVIDER` | `hash` | `sentence_transformers` (real), `hash`, or `fake` |
| `EMBED_MODEL` | `BAAI/bge-small-en-v1.5` | Embedding model name |
| `EMBED_DIM` | `384` | Must match the DB vector column |
| `RERANK_MODEL` | `BAAI/bge-reranker-base` | CrossEncoder reranker model |
| `RELEVANCE_THRESHOLD` | `0.35` | Minimum score to answer; below → refusal |
| `JWT_SECRET` | *(insecure dev default)* | **Change in production** (≥ 32 random bytes) |
| `STORAGE_BACKEND` | `local` | `local` or `s3` |
| `UPLOAD_DIR` | `/tmp/docchat/uploads` | Local upload path |
| `MAX_UPLOAD_MB` | `25` | PDF file size limit |
| `MAX_PAGES` | `300` | PDF page count limit |
| `CORS_ORIGINS` | `http://localhost:5173` | Comma-separated allowed origins |
| `SMTP_HOST` / `SMTP_USER` / … | *(empty)* | SMTP config for email invitations |
| `RESEND_API_KEY` | *(empty)* | Alternative to SMTP (Resend) |
| `DAILY_QUESTION_QUOTA` | `100` | Questions per user per day |
| `RATE_LIMIT_PER_MINUTE` | `30` | General API rate limit |
| `CHAT_RATE_LIMIT_PER_MINUTE` | `10` | Chat endpoint rate limit |

## Security

| Concern | Implementation |
|---|---|
| **Password hashing** | Argon2id via `argon2-cffi` |
| **Auth tokens** | 15-min JWT access tokens (in-memory) + 14-day opaque refresh tokens in `httpOnly; Secure; SameSite=Lax` cookies with automatic reuse revocation |
| **Multi-tenancy** | Server-derived `WorkspaceContext`; cross-tenant requests → 404 |
| **Upload validation** | `%PDF-` magic byte check, 25 MB limit, 300 page limit |
| **Prompt injection** | Document chunks wrapped in literal `<source>` tags |
| **Input sanitization** | Filenames sanitized, stored under UUID paths; HTML output sanitized against XSS |
| **Security headers** | `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` on every response |
| **Error leaks** | RFC 7807 problem responses; no stack traces or document content in errors/logs |

See [`docs/SECURITY.md`](docs/SECURITY.md) and [`docs/AUTH.md`](docs/AUTH.md) for the full security spec.

## Deployment

### Render / Railway (one-command)

The repo ships ready-to-deploy configs:
- [`deploy/render.yaml`](deploy/render.yaml) — API + worker + managed PostgreSQL 16
- [`deploy/railway.json`](deploy/railway.json) — Railway service definition

> [!IMPORTANT]
> Set `STORAGE_BACKEND=s3` with a proper S3-compatible bucket in production — local disk is ephemeral on PaaS platforms.

### Production checklist

- [ ] `JWT_SECRET` is unique and ≥ 32 random bytes
- [ ] `CORS_ORIGINS` lists only your actual frontend origin(s)
- [ ] `alembic upgrade head` runs as a pre-deploy step
- [ ] Managed Postgres has `CREATE EXTENSION vector;` enabled
- [ ] Object storage configured for PDF persistence
- [ ] Automated backups and alerts enabled
- [ ] Sentry DSN set for API, worker, and frontend
